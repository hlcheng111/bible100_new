# 小白上雲包（靜態站 → 雲端）

你**不必會寫程式**也能照順序做。工程師接手時再改 `church_data_bridge.js` 接 API。

---

## 一、先釐清：兩種「上雲」

| 做法 | 誰能做 | 結果 |
|------|--------|------|
| **A. 只把網頁放到主機** | 會用 FTP／Git／主機後台即可 | 大家用瀏覽器開得到頁面，**資料仍在各人電腦的 localStorage**（不算真正雲端資料庫） |
| **B. 雲端資料庫 + API** | 需後端／工程師 | 多裝置、多人、備份、權限，**這才是「正式上雲」** |

本站的 **`USE_API`** 是為 **B** 預留開關；**沒有後端前請保持 `USE_API: false`**，否則畫面可能報錯。

---

## 二、你要改哪一個檔？（只改這裡）

檔案路徑：

```
bible100_new/js/cloud_config.js
```

用記事本或 VS Code 打開，只會看到幾行，例如：

```javascript
USE_API: false,
API_BASE_URL: '',
```

### 本機／示範（維持現狀）

- **`USE_API`** 保持 **`false`**（不要改）。
- 不用填 `API_BASE_URL`。

### 以後有後端 API 時（交給工程師）

1. 工程師給你一個網址，例如：`https://你的教會.org/api/v1`
2. 把 **`API_BASE_URL`** 改成這個字串（結尾不要亂加斜線，依工程師說明為準）。
3. **`USE_API`** 改為 **`true`**（**僅在** `church_data_bridge.js` 已接上 `fetch` 之後）。

> **小白請記：** 單改 `true` 而沒有後端，頁面**不會**自動變好，還需要工程師完成「Bridge 內改 fetch」。

---

## 三、`USE_API` 與 `church_data_bridge.js` 的關係（給工程師看）

- **`cloud_config.js`**：開關與網址。
- **`church_data_bridge.js`**：所有 `localStorage` 讀寫應在這裡改成「先判斷 `USE_API`，再 `fetch`」。
- 已提供輔助：**`bible100_new/js/cloud_api.js`** 的 `churchCloudFetch(...)`，可統一加網址與錯誤提示。

小白**不用**自己改 `church_data_bridge.js`，交給工程師即可。

---

## 四、上雲前要先「清掉舊站」嗎？

**不一定。**

| 情況 | 建議 |
|------|------|
| **新網域／新主機** | 不用清舊站；新站部署好後，把網域 **DNS 指到新主機** 即可。 |
| **同一主機覆蓋舊檔** | 先 **備份** 舊站資料夾，再上傳新檔，避免失手。 |
| **舊站有資料庫** | 要 **遷移／匯出**，不是「刪站」就沒事；需與工程師規劃。 |

**重點：** 靜態 HTML 沒有「伺服器上的舊資料庫」要清；要清的是 **主機上舊的網頁檔**（若你要換版），且一定要先備份。

## 五、上雲檢查清單（小白版）

- [ ] 網頁用 **HTTPS**（瀏覽器才會正常處理現代功能與安全）。
- [ ] 重要資料：**匯出 JSON／備份**（會友、探訪等），不要只靠單一瀏覽器。
- [ ] **權限**：誰能看奉獻、探訪，需後端帳號（本靜態站無登入）。
- [ ] **合規**：個資、奉獻紀錄，依教會政策保存。

## 七、遇到問題時

1. **先改回** `USE_API: false`，確認本機模式是否正常。  
2. 把 **瀏覽器 F12 → Console** 的紅色錯誤截圖給工程師。  
3. 說明是「只放靜態檔」還是「已接上後端 API」。
