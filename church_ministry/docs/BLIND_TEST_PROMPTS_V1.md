# 教會事工 · 中立 AI 盲測提示包（V1）

> 用途：把下面任一段貼給**沒看過這個專案**的 AI（建議換不同廠牌各跑一次），再把它的報告貼回來。
> 「盲」＝AI 不知道我們想聽什麼、也不先看我們自己的檢查報告，只根據它**實際看到的畫面與頁面**下判斷。
> 2026-11-25 已用 3 個子 AI 跑過一輪（見 `audit/stage4/blind_*.md`）；外部 AI 的結果可與其比對。

## 0. 先給 AI 的材料（二選一）

| 方式 | 給什麼 | 適合 |
|---|---|---|
| A. 截圖包 | `church_ministry/audit/stage2/screens/*/`（每頁一張）＋`audit/stage3/screens/`（流程每步） | 沒有檔案權限的聊天型 AI |
| B. 專案資料夾 | 整個 `bible100_new`，**禁止它先看** `church_ministry/audit/`、`docs/ZONE_*`、`docs/MRM_*` | 能讀檔案的 Agent 型 AI |

入口（B 方式）：`church_ministry/index.html`；各區頁面清單見 `church_ministry/docs/ZONE_PAGE_MAP_V1.md` 的「頁名」欄（只讀頁名，不讀它的結論欄）。

## 1. 通用模板（每次都用；把 `{角色}` `{範圍}` 換掉）

```
你是一位獨立的產品檢測員，沒有看過這個專案，也不認識它的作者。
請以【{角色}】的身份，檢測「教會事工」網站的【{範圍}】。

【情境】這是給華人教會同工使用的管理網站，可離線在電腦上開（file://）。

【規則】
1. 只根據你「實際看到」的畫面／頁面內容判斷；看不到就寫「無法判斷」，不要猜、不要客套。
2. 每個發現都要附證據：頁面路徑＋你看到的原文或畫面位置。沒有證據的不要寫。
3. 嚴重度：P0 資料會壞或洩漏／P1 主要功能不能用／P2 能用但容易做錯或看不懂／P3 小瑕疵。
4. 不要改任何東西，只報告。
5. 不要因為頁面「看起來完整」就給高分；請真的照步驟走一遍。

【請逐頁回答】
- 這頁是做什麼的？（一句話；你看不懂就寫看不懂）
- 我（{角色}）第一眼知道要按哪裡嗎？（是／否＋原因）
- 按了主要按鈕之後，結果合理嗎？（寫你按了什麼、看到什麼）
- 有沒有空白、亂碼、undefined、按了沒反應、文字截斷、中英／簡繁混雜？
- 資料存了之後，換頁再回來還在嗎？

【輸出】
A. 頁面表：頁面｜用途｜第一眼分數(1-5)｜可完成任務？(是/部分/否)｜問題(附證據)｜嚴重度
B. 最嚴重的 3 個問題＋各自「怎麼重現」（步驟 1、2、3）
C. 整體分數（1-10）＋一句話理由＋你最不放心的一件事
D. 一張 Mermaid 流程圖：你認為使用者在這個範圍內「應該怎麼走」，並標出你實際卡住的位置
```

## 2. 三個角色（替換 `{角色}`）

| 角色 | 一句話設定 | 重點看 |
|---|---|---|
| 小白 | 第一次接手教會行政的志工，不懂電腦術語，只會照畫面做 | 3 次點擊內找到事？文案看得懂？按錯會不會闖禍？有沒有「不能按」的提示？ |
| 學者 | 神學／牧養背景的同工，在意教義與牧養倫理，會細讀文字 | 用語是否合宜、有無把人當「數據」、AI 建議有沒有標明需人審、個資處理是否令人安心 |
| 專家 | 做過 ERP／CRM 的系統分析師 | 資料是否一致（同一個人在各頁是否同一筆）、有無閉環、匯出入、備份還原、權限、錯誤處理 |

## 4. 加碼題（跨區流程，只給專家／小白）

```
請在【教會事工】網站，用全新空白資料走下面這條流程，每一步都記錄「我按了什麼／看到什麼／
資料有沒有出現在下一頁」。卡住就停，並寫出卡在哪一步、原因、你期待看到什麼。

流程 {F1~F5 擇一}：
F1 新朋友自助登記 → 接待台發碼 → 點名頁用代碼簽到 → 牧養名冊找得到他 → 有人跟進他嗎？
F2 小組成員連續缺席 → 預警名單 → 探訪佇列 → 完成關懷 → 他回來後預警消失
F3 完成初信與門徒課程 → 出席達標 → 被列為提摩太人選 → 晉升 → 在門訓頁看得到
F4 新增排班（故意同人同時段排兩次）→ 請假 → 排班檢查器有沒有抓到 → 補救後提醒消失
F5 備份 → 故意清掉資料 → 還原（含加密備份、輸錯密碼、壞檔）→ 資料是否原樣回來

最後回答：這條流程「一個沒有受過訓練的志工能不能獨立完成？」，若不能，最少要改哪 3 處。
```

## 5. 「宣稱 vs 現實」加碼題（專家用）

```
下面是網站自己的說明文字。請逐條驗證它說的是不是真的（打開對應頁面操作），
給：屬實／部分屬實／不實，並附證據。
{把各頁頂部「這頁能做什麼」的說明貼在這裡，每頁 3~5 句}
```

## 6. 收回報告後怎麼用

1. 把 AI 報告存成 `church_ministry/audit/stage4/blind_<AI名>_<角色>.md`。
2. 與我們自己的階段 1／2／3 報告比對：**兩邊都指到的＝一定要修；只有 AI 指到的＝先複核是不是它誤解；只有我們指到的＝AI 看不出來，多半是技術債。**
3. 看過後再決定修哪些（階段 4）。
