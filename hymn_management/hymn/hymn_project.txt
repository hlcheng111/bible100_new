**技術挑戰**：

```
問題1：數據庫路徑問題
```

```
- 原因：PowerShell 不支持 && 操作符
- 解決：分步執行命令
```

### **1.3 Strong編號處理階段**
**目標**：識別並處理經文中的Strong編號，實現點擊聯動功能。

**技術實現過程**：

**第一版正則表達式**：
```javascript
const strongPattern = /(<W[AHG]\d+>)/g;
```
**問題**：無法匹配 `WAH`、`WTH` 等格式

**第二版正則表達式**：
```javascript
const strongPattern = /(<W[AHG]+\d+>)/g;
```
**問題**：仍然無法匹配所有變體

**第三版正則表達式**：
```javascript
const strongPattern = /(<W[A-Z]+\d+>)/g;
```
**問題**：無法處理 `{<WH...>}` 格式

**最終版正則表達式**：
```javascript
const strongPattern = /(<W[A-Z]+\d+>|{<W[A-Z]+\d+>})/g;
```
**結果**：成功匹配所有Strong編號格式

### **1.4 HTML 渲染問題**
**問題**：Strong編號顯示為純文本，無法應用CSS樣式

**根本原因**：
```html
<!-- 錯誤的HTML生成 -->
<span class="strong-number"><WH0430></span>
```
瀏覽器將 `<WH0430>` 中的 `<` 和 `>` 解釋為HTML標籤，導致外層 `<span>` 被忽略。

**解決方案**：
```javascript
const displayText = match.replace(/</g, '&lt;').replace(/>/g, '&gt;');
return `<span class="strong-number" data-strong-code="${strongCode}">${displayText}</span>`;
```

### **1.5 數據庫查詢API問題**
**問題**：`stmt.all()` 方法不存在

**錯誤代碼**：
```javascript
const results = stmt.all(); // ❌ 方法不存在
```

**正確實現**：
```javascript
const results = [];
stmt.bind([book, chapter]);
while (stmt.step()) {
    results.push(stmt.getAsObject());
}
stmt.free();
```

```javascript
// 新的詞典查詢服務
class StrongDictionaryService {
    constructor() {
        this.strongDb = null;
        this.cbolDb = null;
    }
    
    async initialize() {
        this.strongDb = await loadDatabase('../data/dictionaries/cbol.db');
        // 驗證表結構
        const tables = this.strongDb.exec("SELECT name FROM sqlite_master WHERE type='table'");
        this.valid = tables.some(table => table.name.toLowerCase().includes('strong'));
    }
    
    async queryStrongNumber(number) {
        if (!this.valid) return null;
        
        // 根據實際表結構動態構建查詢
        const query = `SELECT * FROM strongs WHERE number = ?`;
        const stmt = this.strongDb.prepare(query);
        stmt.bind([number]);
        
        const results = [];
        while (stmt.step()) {
            results.push(stmt.getAsObject());
        }
        stmt.free();
        
        return results.length > 0 ? results[0] : null;
    }
}
```

#### **挑戰三：跨數據庫事務**

```javascript
class TransactionManager {
    async executeCrossDbTransaction(operations) {
        const results = [];
        const rollbackActions = [];
        
        try {
            for (const op of operations) {
                const result = await op.execute();
                results.push(result);
                rollbackActions.push(op.rollback);
            }
            return results;
        } catch (error) {
            // 執行回滾
            for (const rollback of rollbackActions.reverse()) {
                await rollback();
            }
            throw error;
        }
    }
}
```

Cursor AI 的真實本質（2025 年版）

基於 LLM，但不止於生成：是的，它還是用 GPT/Claude 等大型語言模型作為大腦，專注生成/建議代碼。但不同於純聊天 AI（如 ChatGPT），Cursor 是基於 VS Code 的 AI 編輯器，它能直接整合到你的開發環境，透過「Agent 模式」和工具來操作文件系統。這是安全設計：它只在你開啟的專案目錄內工作，不會亂碰系統其他部分。
文件操作能力：

創建（Create）：Agent 可以直接生成新文件（e.g., 用自然語言說「創建一個 React 組件文件」），它會自動在你的專案中新增檔案，甚至初始化整個專案結構。早期版本（2023-2024）還有限制，只能建議內容讓你手動創建，但現在（2025）已經成熟，能一鍵應用。
修改（Modify）：這是它的強項！用「Instant Apply」功能，它能以 1000 tokens/秒的速度重寫整個文件（或多文件），基於你的提示自動編輯。用戶反饋顯示，它能處理大規模重構，比如改幾 GB 的代碼庫，而不只是小片段。
移動/刪除（Move/Delete）：支持透過聊天或 Agent 指令移動文件夾、重命名、刪除。社區論壇有用戶請求這功能，現在已經內建（e.g., 提示「移動 src/components 到 lib/」）。
為什麼能處理幾 GB？：它用「規劃 + 應用」兩階段：先用強模型（如 Claude 3.5）規劃變化，再用專門的快速模型應用編輯。加上「@」語法，能輕鬆拉取整個 codebase 作為上下文，避免 copy-paste 麻煩。
