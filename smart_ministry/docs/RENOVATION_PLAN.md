# 🧠 智慧事奉中心 Smart Ministry Center — 重修計劃書

**版本**：1.0（草案，供排程實作）  
**目的**：在保留現有模組價值的前提下，將「智慧事奉」重整為**牧養導向、資料可銜接、導航正確、技術可演進**的子系統；與全站 **會友主檔（memberId）**、**教會事工中心** 敘事一致。  
**實作原則**：有額度時**分階段**落地，每階段可獨立驗收。

---

## 一、理念與定位

### 1.1 核心定位

- **基督是教會的頭**，信徒按恩賜彼此服事；本模組是**輔助工具**，不取代聖靈引導、牧者分辨與禱告。
- 產出僅為**建議／雷達**，不是派工命令；事奉是**恩典**，需禱告與對話。
- **多維度看人**：恩賜、品格、呼召、家庭、時間負荷等，避免把人工具化或「人力資源化」。
- **心理／性格工具**（如 MBTI）：僅作性格與配搭參考，**不等同屬靈光景**、不當服事門檻；頁首與結果頁須反覆聲明。

### 1.2 對象與場景

- **微、小、中教會**：補人力、降低被忽視感，強調牧養語氣，而非效率／KPI。
- **東南亞、山區、低資源環境**：說明文字**低術語**、可列印**簡短講義（1–2 頁 PDF）**、允許**紙本填寫再代為輸入**。

### 1.3 模組首頁（或總覽）建議標語

> 「這不是績效系統，而是幫助我們一同看見神在每位弟兄姊妹身上的工作。」

## 二、資訊架構：一條「服事生命線」

將下列區塊視為**同一條線**，而非四個互不相干功能；使用者與教牧能看見「從認識恩賜 → 配對 → 參與 → 回顧 → 裝備 → 成長」的連續故事。

**建議流程（頂部流程條，每個功能頁都顯示）：**  
`認識／測驗 → 配對建議 → 參與服事 → 牧養式評估 → 培訓裝備 → 服事成長路徑`

## 三、內容與功能頁規劃

### 3.1 屬靈恩賜測驗（兩層＋教學）

| 層級 | 目的 | 建議形式 |
|------|------|----------|
| **快篩版**（約 8–12 題，10 分鐘內） | 新來者體驗、即時方向與配對入口 | 情境題＋4 點量表；類別覆蓋教導、關懷、帶領、服事實作、佈道、禱告、行政、創意等；結果為**前 2–3 恩賜群組＋初步事奉建議**，並引導進階測驗 |
| **進階版**（約 40–60 題） | 與輔導／教牧深入討論 | 依羅 12、林前 12、弗 4 簡化為 8–10 類；每類多題；結果避免「你沒有某恩賜」，改為「較不明顯／尚未顯示」 |
| **教牧／領袖教學頁** | 正確使用測驗與配對 | 獨立頁：定位、對話方式、避免標籤化、與牧者同行、資料界線 |

**資料**：每次測驗存一筆 `GiftAssessmentResult`（含 `schemaVersion`／題組版本、日期、分數物件）。

---

### 3.2 智能配對（規則引擎優先）

- **第一版**：規則引擎（非黑箱 ML）；權重可設定（例如：時間可行性、恩賜匹配、性格微調、過載懲罰、教會階段性優先）。
- **輸出**：Top N 建議＋理由標籤＋**信心等級**；必含「與牧者分享／討論」提示。
- **存檔**：每次執行寫入 `MatchingHistory`（候選、分數、規則版本），即使尚未接受崗位。

---

### 3.3 「📊 人才發展追踪」子線（四頁一體）

下列須與**同一 believer／memberId** 關聯，並在 UI 上共用**流程條**與**非績效**聲明。

| 頁面／功能 | 角色 | 重修要點 |
|------------|------|----------|
| **成長記錄**（`talent_tracking.html`） | 個人＋牧者 | 上半部：**個人摘要卡**（姓名、受洗、主要服事、最近測驗日）；中間：**時間線**（參與、培訓、崗位變化）；下半部：**目前專注／下一步建議**（連培訓與路徑頁）。少用「KPI」字樣，或改「服事回顧指標」並附牧養免責說明。 |
| **服事評估**（現 `assessment.html` 與「恩賜測驗」須分離） | 帶領同工填寫 | **非**企業考績：每段服事一小卡——忠心度／合適度／團隊配搭（三級）＋**鼓勵與建議**短句；頁首說明目的為牧養與配搭。 |
| **培訓需求**（`skills_expertise.html` 等） | 個人＋牧者 | **裝備地圖**：上區**依恩賜＋評估自動建議課程**；中區**教會課程一覽**（JSON）；下區**已完成／預計參加**時間線。 |
| **服事成長路徑**（現 `talent_acquisition.html` 內容與名稱不一致） | 教導、初信者 | **避免「升官」聯想**：頁首用「服事成長路徑」；2–3 條**典型示例**（接待線、教導線等）；每階段說明成熟度與裝備；**明註**：有人長期忠心同一崗位同樣貴重。 |

**導航修正（現況問題，實作時優先處理）**

- `assessment.html` 目前實為**屬靈恩賜測驗**，側欄卻標「表現評估」→ **需分檔或分頁**：恩賜測驗 ≠ 服事評估。
- `talent_acquisition.html` 目前為**人才吸納中心**→ **與「晉升／成長路徑」分離**：吸納一頁、路徑另一頁（或改選單連結）。

## 四、技術改進

### 4.1 資料模型（概念層，可存 localStorage／日後 API）

- `Believer`（或僅存 `memberId`＋本模組擴充欄位）
- `GiftAssessmentResult`（含版本號）
- `PersonalityProfile`（MBTI／DISC 等，輔助權重低）
- `MinistryRole`（崗位、所需恩賜權重、時間、限制）
- `MatchingHistory`（每次配對快照）
- `DevelopmentTracking`（實際參與崗位、期間、簡評）
- `ServiceEvaluation`（牧養式評估，依服事紀錄）

事件進時間軸時，盡量帶 **`assessmentRunId`／`matchingRunId`**，便于追溯。

### 4.2 規則引擎

- 以 **JSON 設定權重與崗位矩陣**，便於東南亞／山區牧者**不寫程式**也能調整策略。
- 預留 **pseudocode／註解** 對外說明，增強教會信任。

### 4.3 前端與 UX

- **殼頁＋ iframe**：維持現狀可接受；長期可評估改為單頁分頁以降低巢狀 iframe。
- 側欄選單**預設展開第一區**或加**短引導**，避免「只看到標題、沒有連結」。
- 統一 **繁／簡** 與用語（牧養詞彙優先）。
- 字級不宜過小（側欄 8px 級不利無障礙）。

### 4.4 文件與對外說明

- 可在 **`help/global-tools.htm`** 或本目錄 **`README.md`** 加入本計劃連結，方便長執與支援者理解。
- **教牧使用指南**單頁：如何讀恩賜、評估、成長記錄；誤用案例與界線。
- **已掛號之指南與全站 landing 原則**：`guide_for_leaders.html`（牧者／同工）、全站說明見 repo 根下 **`docs/LANDING_UX_PRINCIPLES.md`**。

## 五、分階段實作建議（有額度時）

| 階段 | 內容 | 驗收要點 |
|------|------|----------|
| **P0** | 修正側欄與檔案對應（恩賜測驗／服事評估／吸納／成長路徑）；各頁加流程條＋標語 | 導航無誤導；點擊可達正確頁 |

| **P4** | 與 `memberId`／API 同步；教學頁與 PDF 講義 | 可給牧者審閱 |

## 六、非目標（避免範圍爆炸）
