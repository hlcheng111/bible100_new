# Bible 100 專案總體分析與戰略行動計劃

**文件版本:** 1.0
**更新日期:** 2024-07-26

## 1. 總體架構評估 (Overall Architecture Assessment)

本專案是一個典型的「靜態內容網站」與「動態 Web 應用」的混合體。其核心價值在於豐富的聖經課程內容，同時規劃了具備高度互動性的管理與 AI 工具。

**當前主要挑戰:**

1.  **性能瓶頸:** 核心課程內容 (`chapter*.html`) 檔案體積過於龐大（數 MB），內嵌了大量圖片資源，導致頁面加載時間極長，嚴重影響用戶體驗，這是目前最致命的問題。
2.  **功能孤島 (Functional Silos):** 各大模組（如 `languages`, `bible_comparison`）之間缺乏統一的導航、頁面佈局和設計風格，用戶在不同功能間跳轉時會感到體驗割裂。
3.  **響應式設計缺失:** 現有頁面多為固定寬度佈局，在平板電腦和移動設備上的顯示效果不佳，無法滿足多樣化的設備需求。
4.  **手動維護成本高:** 網站地圖 (`sitemap.html`)、導航連結等需要手動更新，隨著內容擴展，維護將變得異常困難且容易出錯。

## 2. 模組功能分析與建議 (Module Analysis & Recommendations)

| 模組名稱 | 功能定位 | 分析與建議 |
| :--- | :--- | :--- |
| **Languages (核心內容)** | 提供多語言的聖經課程 | **問題:** `chapter*.html` 性能問題是重中之重。缺乏統一的語言/課程選擇入口。<br>**建議:** 必須將內容與表現分離，把 `chapter*.html` 重構為「HTML 範本 + JSON 資料」的模式，按需加載。創建 `languages/index.html` 作為所有語言的導覽頁。 |
| **SiteMap (網站地圖)** | 提供網站結構，輔助導航與 SEO | **問題:** 靜態手動維護。<br>**建議:** 轉為動態生成。編寫腳本在頁面加載時掃描專案結構，自動生成可互動（可搜索/過濾）的站點地圖。 |
| **Search (全站搜尋)** | 提供內容搜尋能力 | **問題:** 功能完全缺失。<br>**建議:** 分階段實施。第一步，通過預處理腳本生成內容索引 (JSON)，利用 `Lunr.js` 等客戶端函式庫實現快速的離線搜尋功能。 |
| **Bible Comparison (聖經比較)** | 並排比較不同聖經版本 | **問題:** 在平板直向模式下，並排佈局體驗差。<br>**建議:** 在全局響應式設計中，為此類工具頁面設計特定斷點，在小螢幕下自動切換為縱向標籤頁 (Tab) 佈局。 |
| **School Mtg / Church Mtg** | 教學與教會管理應用 | **問題:** 屬於複雜的動態應用，依賴後端和資料庫。<br>**建議:** 作為遠期獨立子專案處理。初期僅創建靜態介紹頁面，標註「即將推出」。 |
| **Bible Study AI / AI Tools** | AI 賦能的學習工具 | **問題:** 技術複雜度高，依賴外部 LLM API。<br>**建議:** 作為高階亮點功能，在核心網站體驗穩定後，從一個小型、單點的 AI 工具（如經文問答）開始試點開發。 |
| **Children's / Advanced** | 預留的內容擴展模組 | **問題:** 尚未開發。<br>**建議:** `Children's` 應注重互動性和趣味性；`Advanced` 應注重學術性和工具性。在主體架構完成後再進行規劃。 |

## 3. 戰略性行動計劃 (Strategic Action Plan)

我們將採用分階段、由內而外、從基礎到上層的策略，確保在健康的基礎上構建功能。

---

### **第一階段：基礎設施重建 (Phase 1: Infrastructure Reconstruction)**

此階段目標是徹底解決核心性能與體驗問題，為後續所有功能開發鋪平道路。

- **[P0] 1.1 內容性能優化 (Content Performance Optimization):**
    - **任務:** 將 `chapter*.html` 檔案解構成「輕量級 HTML 範本」和「內容資料檔 (JSON)」。圖片等靜態資源外部化。
    - **目標:** 實現頁面秒級加載。
- **[P1] 1.2 統一導航與佈局 (Unified Navigation & Layout):**
    - **任務:** 創建一個全局共享的頁首 (Header) 和頁腳 (Footer)。頁首應包含 Logo、主導航（連結至各大模組）、語言切換器。
    - **目標:** 建立一致的用戶體驗，打破功能孤島。
- **[P1] 1.3 全局響應式設計 (Global Responsive Design):**
    - **任務:** 創建一個全局 `responsive.css` 檔案，使用 Flexbox 和 Grid 等現代佈局技術，並應用於新的統一佈局中。
    - **目標:** 確保網站在桌面、平板和手機上均有良好的瀏覽體驗。

---

### **第二階段：核心功能增強 (Phase 2: Core Functionality Enhancement)**

在網站基礎穩固後，增加提升可用性的核心功能。

- **[P2] 2.1 動態網站地圖 (Dynamic Sitemap):**
    - **任務:** 實現動態生成站點地圖的腳本。
- **[P2] 2.2 客戶端搜尋 (Client-Side Search):**
    - **任務:** 創建內容索引生成腳本，並在前端集成 `Lunr.js` 或 `Fuse.js` 實現搜尋功能。

---

### **第三階段：高級應用開發 (Phase 3: Advanced Application Development)**

在核心網站功能完備後，開始探索和開發高級模組。

- **[P3] 3.1 規劃與試點 (Planning & Pilot):**
    - **任務:** 從 `AI Tools` 或 `School Mtg` 中選擇一個最小可行性功能（MVP）進行試點開發，驗證技術方案。
