## 3. Q1 · 小白 — Topbar 是否夠任務導向？

### 3.1 診斷

| 問題 | 嚴重度 | 說明 |
|------|--------|------|
| 「釋經參讀」偏術語 | 中 | 主日學老師更熟「看註釋／備課」 |
| 「對照」無上下文 | 低 | 不知比什麼 |
| 「📡 資料」非任務 | 高 | 像 IT 狀態頁，小白不敢點 |
| 六鍵並列 | 中 | 選擇疲勞；缺「我現在該做哪一步」 |

### 3.2 建議文案（任務動詞 + 副標 tooltip）

| 現文案 | 建議主文案 | `title` 副標（滑鼠提示） |
|--------|------------|-------------------------|
| 📖 閱讀 | **讀經文** | 單章閱讀 · 左經右註 |
| 🔍 釋經參讀 | **看註釋** | 綜合解讀 · 備課用 |
| 📑 對照 | **比譯本** | 中英／多語對照 |
| 📡 資料 | *移出主列* 或 **檢查資料** | 給同工／牧長；預設收進功能地圖 |
| ❓ 難題 | **同章難題** | 換模組 · 聖經 Q&A |
| 🧭 功能地圖 | **全部工具** | 詞典、串珠、原文… |

### 3.3 建議 IA（仍 5 個「小白可見」主鍵）

```
[ 讀經文 ] [ 看註釋 ] [ 比譯本 ] [ 同章難題 ] [ 全部工具 ▾ ]
                                              └─ 含：搜尋、資料綠燈、版本中心
```

- **搜尋**：保留在 Topbar 輸入框（已是肌肉記憶），不必再占一顆任務鍵。  
- **📡 資料**：改為功能地圖內第一張卡片 + 牧長模式才上 Topbar（見 Q3）。

### 3.4 肯用驗收（小白）

- [ ] 新用戶不看說明，能在 3 分鐘內從 Topbar 進入「讀創世記 1 章」  
- [ ] 能說出「看註釋」和「讀經文」差別  
- [ ] 點「同章難題」時，tooltip／首次提示含「將開新分頁 · 聖經難題模組」

**決策待填**：是否同意「Topbar 只留 5 任務鍵 + 搜尋 + 總站」？ □ 是 □ 否 □ 資料鍵保留

## 4. Q2 · 同工 — 是否缺「一鍵備課包」？

### 4.1 現有能力

| 能力 | 位置 | 缺口 |
|------|------|------|
| PT-01 備課三問 | 釋經／對照／reader 下拉 | 需選模板 + 按複製，**兩步** |
| PT-04 難題銜接 | 同上 | 與 PT-01 分開 |
| QnA 深連 | ❓ 同章難題 | 另開分頁，未併入剪貼板 |
| 經文／註釋 | BibleEngine 懶載入 | 已可注入 Prompt |

### 4.2 建議：「一鍵備課包」（無 API）

**一顆按鈕**：`📋 複製備課包`（釋經頁 Topbar 優先，對照頁次之）

**剪貼板內容順序（固定）**：

1. 章節標題（書卷 · 章 · 譯本）  
2. 經文全文（faith 或當前譯本，≤整章）  
3. 綜合解讀摘錄（≤800 字，本地無則標「需連線 CMC 或補 data/cj」）  
4. QnA 深連 URL 一條（同章）  
5. **內嵌 PT-01 提問框架**（觀察／解釋／應用各 3 問 — 請 AI 依上文生成）  
6. 固定護欄（`PROMPT_TEMPLATES_P3.md`）

**與現有 Prompt 下拉關係**：

- 備課包 = **預設套餐**（80% 同工場景）  
- 下拉 = **進階**（PT-02 對照、PT-05 小語種）

### 4.3 好用驗收（同工）

- [ ] 同一章：釋經 → 複製備課包 → 貼到 ChatGPT，**一次**含經文+註釋+護欄  
- [ ] 從 Topbar「看註釋」進入時，書卷章與 reader 同步（StudyState 已支援，需 UI 明示）  
- [ ] 備課包內 QnA 連結可點，開啟後左欄已篩同章

**決策待填**：備課包按鈕放 Topbar 還是僅釋經頁？ □ Topbar □ 僅釋經 □ 兩者

## 5. Q3 · 牧長 — 本地／CMC 與綠燈是否露出？

### 5.1 診斷

| 現況 | 牧長視角 |
|------|----------|
| 釋經狀態列有「本地綜合解讀 / CMC fallback」 | ✅ 僅在釋經頁底部，**總站 Topbar 看不到** |
| `data_sources.html` 完整綠燈 | ✅ 但藏在 📡 資料，小白誤觸 |
| 無「本教會資料就緒度」摘要 | ❌ 無法開會前 30 秒確認 |

### 5.2 建議：輕量「資料狀態 chip」（牧長模式）

**位置**：Topbar 品牌右側，或 `currentPosition` 旁

| 顯示 | 條件 |
|------|------|
| 🟢 本地資料就緒 | registry 核心譯本 + 綜合解讀 json/db 可 probe |
| 🟡 部分本地 | 有經文、無本地釋經 → 釋經走 CMC |
| 🔴 僅線上／缺檔 | file:// 或 data 缺 |
| ☁️ 釋經：雲端補充 | 當前章為 CMC fallback |

**互動**：點 chip → 右欄 `data_sources.html`（不換左欄側欄 ✅）

**牧長模式開關**（避免嚇小白）：

- 預設 **關**：chip 僅 🟢/🟡/🔴 三色點，無文字  
- 開：顯示完整文案 + 最後掃描時間  
- 設定存 `localStorage` `bible_study_pastor_mode=1`

### 5.3 與 CMC 的信任邊界（文案）

釋經頁 CMC fallback 時，固定一行（牧長可審）：

> 本地綜合解讀不可用；目前為 **CMC 雲端釋經（需連線）**，內容供參考，正式教材以本地授權資料為準。

- [ ] CMC fallback 是否必須標示在 Topbar chip，還是釋經頁內即可？

## 6. Q4 · 工程 — BS 細編號是否放 footer？

### 6.1 現況

- 細表：[`PAGE_MATURITY_BS.md`](./PAGE_MATURITY_BS.md)（BS-L0-01、BS-01…）  
- 全站前綴：[`SITE_PAGE_REGISTRY_V1.md`](../../docs/governance/SITE_PAGE_REGISTRY_V1.md)  
- **頁面 UI 未顯示編號**

### 6.2 四身份權衡

| 顯示 footer 編號 | 利 | 弊 |
|------------------|----|----|
| 小白 | — | 噪音、像 debug |
| 同工 | — | 無幫助 |
| 牧長 | 回報問題可精準說「BS-01」 | 需教育一次 |
| 工程 | 對照成熟度表、測試、issue | — |

### 6.3 建議：**分級顯示，預設隱藏**

| 層級 | 內容 | 誰看得到 |
|------|------|----------|
| L0 | 無 footer | 小白預設 |
| L1 | `BS-01` 小字灰 footer | URL 加 `?debug=1` 或 **工程模式** |
| L2 | `BS-01 · comprehensive_exegesis_reader · 本地優先` | `data_sources.html`、成熟度 HTML 報表 |

**工程模式**：與牧長模式類似，`localStorage bible_study_engineer_mode=1` → 所有 L5 主線頁 footer 顯示 BS 編號 + 頁面檔名。

**不在生產 UI 預設顯示的原因**：憲法要求頂欄小標＝**模組正式名**，不是編號；編號給「編號追」身份即可。

## 8. 任務劇本（驗收用 · 四身份各一條）

### 小白 · 「第一次備課創 1」

1. 開 `bible_study/index.html`  
2. Topbar 點 **看註釋** → 創世記 1 章  
3. 讀完點 **同章難題**（知會新分頁）  
4. **全部工具** 找詞典（可選）  
5. 🏠 總站回家  

### 同工 · 「週六前備好主日學」

1. 看註釋 → **複製備課包** → 貼 AI → 人審  
2. 需要譯本差異 → **比譯本** → PT-02  
3. 疑難 → QnA 深連篩選題  

### 牧長 · 「開會前確認資料」

1. 看 Topbar chip 🟢/🟡/🔴  
2. 點入綠燈頁確認綜合解讀、NIV 是否在列  
3. 抽測一章：本地 or ☁️ CMC  

### 工程 · 「回報問題」

1. `?debug=1` 看 footer `BS-01`  
2. 對照 `PAGE_MATURITY_BS.md`  
3. 跑 `python tests/test_bible_study_data_registry.py`
