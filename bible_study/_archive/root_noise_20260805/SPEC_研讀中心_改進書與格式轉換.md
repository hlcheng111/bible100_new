# 聖經研讀中心 — 功能與技術改進書（含：格式轉換功能頁）
> 討論稿／記錄用（可直接拿去排期與實作）
>
> **對象**：小白用家（低設定、路徑清楚、錯誤可理解）  
> **目標**：可獨立運作（本機）＋可上雲（同一套邏輯可部署／可同步）  
> **更新日期**：2026-03-26

---

## 0. 一句話摘要
把研經產品收斂成「**三步主線**（選資料 → 選章節 → 選功能）」；資料面做到「**掃描＋模板匹配＋fallback**」不破局；體驗面做到「**手機可用、搜尋夠快、狀態可理解**」；AI 面做到「**同屏上下文、金鑰與用量透明、先文字後多媒體**」。

---

## 1. 設計原則（用來校驗每個頁面/功能）
1. **一條主線敘事**：先「讀哪份資料」→ 再「讀哪章」→ 再「要做什麼」（閱讀／比較／搜尋／串珠／AI）。
2. **自動 ≠ 萬能**：自動偵測必須有「模板分類」與「fallback」；失敗要可操作（不是空白）。
3. **效能即果效**：搜尋若慢就等於功能不可用；必要時使用 FTS5 或預建索引。
4. **手機同等重要**：多欄比較在窄屏必須有單欄/Tab 切換或橫向捲動的可用方案。
5. **本地 vs 雲端清楚分層**：不登入也能完整研讀；雲端是可選加值（同步、分享、跨裝置）。
6. **AI 同一上下文**：AI 不是獨立站；要能拿到「引用 + 經文 + 來源名稱 + 使用者選取段落」。
7. **金鑰/用量透明**：第一次使用 AI 前就說清楚「需要 API Key／是否限額／誰付費」。

## 3. 舊頁/舊功能：建議移除、隱藏、或合併（以「減少迷路」優先）

### 3.1 導覽入口收斂（避免像多套軟件）
- **Topbar 重複入口**：
  - 現況有「📊 總覽」與「🏠 主頁」同指向 `dashboard.html`。
  - **建議**：只保留一個入口（例如「功能地圖」），另一個改成「回到預設閱讀」或移除。

### 3.2 多個閱讀器/對照器變體（避免文件、實際使用、維護分裂）
- 專案內常見會有 `*_reader.html`、`parallel_mode_v3.html` 等實驗頁。
- **建議**：
  - 只保留 1–2 條「正式使用路徑」（例如：純閱讀 / 研經工作台 / 對照工作台）。
  - 其他頁面可保留在 repo（供開發），但**不要在小白主線導覽曝光**。

### 3.3 佔位功能（避免「點了沒反應」）
- `功能狀態說明.md` 已指出部分工具列按鈕為佔位。
- **建議**：主線頁面上 **隱藏佔位按鈕**，或改為「即將推出」並連到說明頁。

## 4. 新增/強化頁面（以「三步主線」重新組織）

### 4.1 Dashboard（唯一主入口）
**目的**：小白一進來就知道「下一步做什麼」。

- **UI**：三步導覽條（Step 1 選資料來源 → Step 2 選章節 → Step 3 選功能）
- **區塊**：
  - **最近閱讀**（可一鍵回到上次位置）
  - **資料來源狀態**（版本/註釋/字典/串珠是否可用）
  - **常用功能捷徑**（閱讀、比較、搜尋、註釋同屏、AI 解釋）

### 4.2 資料來源中心（必做）
**小白敘事**：把檔案放進資料夾 → 按重新掃描 → 變綠燈即可用。

- 顯示：已偵測 `.db`、USFM、CSV、Excel；各資料集的「類型/語言/可用功能」。
- 支援：重新掃描、修正欄位（fallback）、索引狀態（建置中/完成）。

### 4.3 比較工作台（收斂 parallel_mode）
- **桌面**：2–4 欄並排
- **手機**：單欄顯示 + Tab 切換來源（或橫向滑動）
- **功能**：欄位可插入「註釋」來源（不是只限聖經文本）

### 4.4 經文 + 註釋同屏（研經核心）
**難點**：節級對齊 + 多註釋排版。

- 同一節底下顯示多本註釋：長文預設折疊、可展開；清楚標示出處與書名。

### 4.5 匯出給 AI（整合到研經流程，不是獨立站）
**現況**：`global-tools` 主要複製 Title + URL（對本機/內網連結的 AI 幫助有限）。

**改良目標**：一鍵複製「引用 + 經文片段 + 來源名稱 +（可選）註釋摘錄 +（可選）教學 prompt」。

### 4.6 第一次使用（Onboarding）
3 分鐘完成：放檔 → 掃描 → 開始讀；並說明「file:// 與 HTTP 模式差異」。

## 5. 核心技術改進（實務落地：模板匹配 + fallback + 索引）

### 5.1 掃描流程（啟動/按「重新掃描」）
1. 掃描資料夾（建議：`../data/bibl/` 或你專案既定路徑）
2. 白名單副檔名：`.db`, `.usfm`, `.sfm`, `.csv`, `.xlsx`（必要時 `.zip`）
3. 大小上限（例：200MB）與非同步處理（避免卡 UI）
4. 若為非 `.db`：進入「格式轉換」流程（見第 6 節）
5. 對每個 `.db`：
   - 讀取 schema（`PRAGMA table_info` / `sqlite_master`）
   - 嘗試模板匹配（見 5.2）
   - 成功：註冊為可用資料來源
   - 失敗：顯示 fallback UI（讓用家手動指定欄位）並儲存設定

### 5.2 模板匹配（Template Catalog）
> 目標：覆蓋「大多數常見資料庫」，少數例外用 fallback 收斂。

- **BibleText**：`Book`, `Chapter`, `Verse`, `Text`
- **Commentary**：`Book`, `Chapter`, `Verse`, `Content`
- **Dictionary (Strong)**：`StrongID`, `Word`, `Meaning`（或近似欄位）
- **CrossRef**：`FromBook/FromChapter/FromVerse` + `ToBook/ToChapter/ToVerse`（或單一引用欄）
- **ParallelGospel**：事件/段落 ID + 多個引用欄（或關聯表）

> 實務提示：模板匹配不必追求完美；要追求「可解釋、可修正、下次可重用」。

### 5.3 Fallback（欄位手動指定 + 設定保存）
當資料庫無法自動辨識時，UI 顯示：
- 「此資料庫未能自動辨識欄位，請選擇：書卷欄／章欄／節欄／正文欄」
- 下拉選單列出所有欄位名稱
- 按鈕：「儲存設定，下次自動套用」

**設定保存格式**：建議每個資料集旁存 `dataset.json`（或集中管理 `datasets.json`），至少記錄：
- dataset id、檔名/路徑、類型（bible/commentary/dict/crossref）
- 表名、欄位映射、語言標籤、顯示名稱
- 是否已建立全文索引（FTS）與索引版本

### 5.4 全文搜尋效能（避免拖垮體感）
- 小資料可 `LIKE` 起步
- 大資料建議：
  - SQLite：FTS5 + 背景建索引
  - JSON：預建索引檔（或轉成 `.db` 再走同一套 FTS）

UI 文案：
- 索引建置中：「正在建索引，請稍候。資料量大時建議使用全文索引（FTS5）。」
- 慢速搜尋提示：「目前為慢速搜尋（未建索引），結果可能需要較長時間。」

## 6. 新增頁：格式轉換功能頁（USFM / CSV / Excel → 標準 `.db`）
> 目的：讓「新加入資料」能被同一套掃描/模板/搜尋管線使用，並降低小白門檻。

### 6.1 功能目標
- 當 `../data/bibl/` 出現新檔：
  - 若不是 `.db`，可轉換成標準化 SQLite `.db`
  - 轉換完成後自動進入掃描註冊（模板匹配 + fallback）

### 6.2 支援格式
- **USFM** → SQLite（可選用 BibleCompiler / USFM-Utils 等工具）
- **CSV / Excel** → SQLite（Python：pandas + sqlite3；或 Node：csv parser + sqlite lib）

### 6.3 產出標準（最小可用）
建立標準表（例：`verses`）：
- `book`（書卷代碼或名稱）
- `chapter`（int）
- `verse`（int）
- `text`（string）
- 可選：`source`（版本名）、`lang`（語言）、`id`（統一 verse key）

### 6.4 轉換頁 UI（小白文案）
- 掃描成功：「已偵測到 5 個資料庫，全部可用。」
- 偵測失敗（fallback）：「此資料庫未能自動辨識欄位，請選擇：書卷欄／章欄／節欄／正文欄。」
- 搜尋慢速：「正在建索引，請稍候。若資料量大，建議使用全文索引（FTS5）。」
- 資料缺失（功能不可用）：「此資料庫缺少交叉參照，功能暫不可用。」

### 6.5 後端偵測/轉換流程（概念）
1. 掃描目錄（非同步）
2. 對非 `.db` 檔案：
   - 進行轉換 → 產生 `.db`
   - 產生/更新 dataset 註冊資訊（dataset.json）
3. 對 `.db`：
   - `PRAGMA table_info` / 模板匹配 / fallback
4. 若需要索引：
   - 背景建 FTS5
   - UI 顯示「索引建置中」

> 重要：若在純靜態 `file://` 環境，通常無法可靠掃描/寫入目錄；此功能建議在「本機伺服器模式」啟用，或採「上傳檔案 → 下載 `.db`」的降級模式。

## 7. AI 整合（先文字、後多媒體；金鑰透明）

### 7.1 必做（第一階段）
- **AI 解釋**：摘要、查經問題、講章大綱（以當前引用與經文上下文為輸入）
- **Prompt 教學**：提供範例 prompt（OIA、釋經/應用分離、教學提問）
- **金鑰/用量說明**（第一次使用前）

### 7.2 後做（風險/成本較高）
- 文生 PPT（先輸出大綱與講義，再接模板工具）
- 文生圖 / 文生視頻（版權、審核、成本、教義表述風險較高）

## 8. 驗收測試清單（Acceptance）
1. 放入 3 個結構不同的 `.db`：
   - 系統自動辨識 2 個
   - 第 3 個觸發 fallback UI
2. 放入 USFM：
   - 自動轉換成 `.db`
   - 轉換後可被掃描、可閱讀章節
3. 放入 CSV/Excel：
   - 自動/手動轉換成 `.db`
   - 轉換後可被掃描、可閱讀章節
4. 大資料搜尋：
   - UI 顯示「正在建索引」
   - 索引完成後搜尋明顯變快
5. 用家手動指定欄位並儲存：
   - 下次掃描可自動套用 `dataset.json`
6. 重複掃描/同名檔案處理：
   - 不誤覆蓋（或有明確覆寫策略）
   - 設定不丟失
7. 手機模式：
   - 多欄比較可用（Tab 切換或橫向捲動）
   - 不會出現「按鈕擠在一起」或不可點

## 9. 實施建議（分階段，避免 16 項變多產品）
- **Phase 0（立刻改善迷路）**：入口收斂、隱藏佔位、三步主線、手機基本可用
- **Phase 1（資料可擴）**：資料來源中心、掃描＋模板＋fallback、搜尋索引策略
- **Phase 2（研經更深）**：比較工作台收斂、註釋同屏（節級對齊 + 排版）
- **Phase 3（AI 先深後廣）**：匯出上下文、AI 解釋、Prompt 教學、金鑰透明
- **Phase 4（上雲可選）**：同步/帳號/隱私/付費策略
- **Phase 5（多媒體）**：PPT/圖/影
