## 1. 總體骨架（適用所有類型）：A～G 七層

每套工具開工前先補齊；缺哪層，之後就會在該場景痛出來。

| 層 | 名稱 | 內容摘要 |
|----|------|----------|
| **A** | 定位與邊界 | 回答什麼／不回答什麼；牧養用途、非臨床、非排名；資料範圍（本機／上雲） |
| **B** | 資料模型 | 欄位、`schemaVersion`、儲存鍵、向後相容與遷移 |
| **C** | 計分或完成度 | 如何把輸入變成可比較狀態（分數、等級、完成率、風險旗標） |
| **D** | 分析輸出 | **L1～L3**（見下節） |
| **E** | 行動與流轉 | **Next best tool**、下一步責任人、與站內其他頁的連結 |
| **F** | 可視化與交付 | 圖表、列印／PDF、匯出 JSON；PDF 需注意可見性與 canvas 時序（見 §6） |
| **G** | 治理與倫理 | 隱私、權限、多人場景、誤用防護、稽核需求 |

## 2. 分析輸出：L1～L3（精華分層）

| 層級 | 名稱 | 內容 | 典型閱讀者 |
|------|------|------|------------|
| **L1** | 儀表 | 只陳述狀態：分數、完成度、落差、關聯是否斷鏈；少形容詞 | 會友／同工快速掃描 |
| **L2** | 規則提醒 | 可解釋的 if／then（門檻、落差、缺欄、矛盾）；牧養語氣、避免假精確 | 牧者覆核、內部一致 |
| **L3** | AI／顧問深化 | 在 L1+L2 **結構化摘要**上產段落（例：給長執會）；須可追溯（引用哪些欄／題） | 會議紀要、深度對話 |

**原則：** L2 每一句盡量對應到「規則 ID 或題號」；L3 不可與 L2 矛盾，只能延伸與組句。

## 3. 依性質分類：演算重心與 L1～L3 配置

### 3.1 調查類（靈命、健康、滿意度、自評…）

- **計分核心：** 維度加總／平均 → 門檻 → **最高與最低維度落差**（常比總分更有牧養價值）。  
- **背景欄：** 預設不進主分；若交叉敘事，僅用極少可辯護規則或交 L3，並在手冊聲明。  
- **開放題：** 以敘事補脈絡；規則層僅輕量標籤或交 AI；避免關鍵字過度推論。  
- **L1～L3：** 雷達／長條 + 整體指數；維度級建議；Prompt 含分數+心聲節錄。  
- **Next tool：** 落差大 → 小組／門訓／牧談流程；紅旗多 → 建議真人同行而非再堆問卷。

#### 3.1.1 調查類 · 工程項目核對（S1～S6）

> 與 **「不導更多問卷 → 導向可執行、可問責下一步」** 直接對應；逐頁檢討靈命／健康／自評等表時可當勾選表。  
> **工程總表**中的上雲前順序與底層核對：`docs/ENGINEERING_MASTER_ROADMAP.md` **§1.5**。

| 編號 | 工程項目 | 目的（可執行／可問責） |
|------|----------|------------------------|
| **S1** | 每張表定義「完成定義」（幾題算可出報告、稀疏時如何降級） | 避免半成品仍給強建議 |
| **S2** | 報告區固定三段：**L1 儀表** → **L2 規則式 1～2 行動** → **Next**（牧談／小組／資源連結，**非**另一份問卷） | 落地在「人與行動」 |
| **S3** | 開放題與分數並陳，Prompt 必含節錄；可選關鍵字輕標籤（可關閉） | 牧養敘事不丟失 |
| **S4** | 匯出單筆 JSON／一頁 PDF（可選含／不含 AI 區） | 交給牧者＝問責載體 |
| **S5** | 暫存 schema 版本化 + 舊欄位相容 | 少壞檔、少「載入失敗」 |
| **S6** | 手冊內寫清：不診斷、不排名、緊急求助資源 | 降低誤用與法律／牧養風險 |

**試行參考實作**：`church_planning/spiritual_app/index_spiritual.html`（統一調查表格呈示與對演算法／匯出之要求時，與 `docs/SURVEY_DESIGN_PRINCIPLES.md` 並讀）。

### 3.2 計劃類（SWOT、SMART、PDCA、Kanban、8020…）

- **「計分」：** 常為完成度 + 品質代理（欄位是否齊、是否矛盾、階段是否卡住）。  
- **分析重心：** **關聯** — SWOT→焦點／TOWS；SMART 承接 SWOT；Kanban 承接 SMART；PDCA 回寫執行與學習。  
- **L1：** 各模組完成率、斷鏈（有 SWOT 無 SMART 等）。  
- **L2：** 規則指出缺哪條鏈、哪個目標無檢核、長期未處理的 W。  
- **L3：** 「給長執會：本季三件事、兩風險、兩個不要做」類段落。  
- **Next tool：** 目標過多 → 8020 或刪減；缺檢核 → Kanban／PDCA。

### 3.3 配對類（恩賜、事工、人才與崗位…）

- **計分：** 多因子相似度／適配度；**忌**單一總分決定一切。  
- **L1：** 排序或分帶、硬性排除（時間不可用等）。  
- **L2：** 解釋「為何推薦」（2～3 個因子）；標註需人工確認欄位。  
- **L3：** 與牧者討論的問句清單、試作 4 週計畫；避免直接「派崗」語氣。  
- **Next tool：** 報名、導師、部門負責人對話頁。

### 3.4 混合型（調查驅動計劃）

- 調查輸出僅作**輸入證據／假設**，進計劃工具時標為「待團隊分辨」；分數不直接變 KPI。

## 5. 跨類型的演算倫理（總體）

1. 先定「量的是什麼」（頻率、同意度、完成與否、負擔…），不同對象不可混用解讀語言。  
2. 分數優先輸出**等級帶 + 落差**，慎防單點小數過度解讀。  
3. 題未答滿／維度稀疏 → **標註資料不足**，仍可給保守建議。  
4. 版本化門檻與 schema，舊報告仍可解釋。  
5. L2 建議盡量可追溯至規則或題號。

## 6. 列印／PDF（常見問題備忘）

- 目標區塊若在 `display:none` 或尚未切換到報告視圖 → 易空白。  
- `canvas` 若未在截圖前完成繪製 → 易空白。  
- 對策方向：`requestAnimationFrame`／短延遲後再匯出；或 canvas `toDataURL` 轉成 `<img>` 再送 PDF；本機 `file://` 與 CDN 行為需實測。

## 7. 資料與「導師總分析」

- **單一裝置 localStorage** 適合：個人暫存、中斷續填、產 Prompt。  
- **導師／長執會「總體分析」** 若要认真：需 **匯出 JSON／CSV** 或 **後端同一 schema**；瀏覽器單鍵無法承載全會眾聚合與權限。

## 9. 四類工具改善工程項目（Phase 1-4 落地）

> 這是「盤點完成後」的標準施工路線，避免只做文檔不做導流與治理。

### Phase 1（短、必做）— Next 導流收斂

- 將盤點主表之 `Next` 欄位由 `Y/待補` 改成**真實站內路徑**。  
- 原則：不再導向「再填一份問卷」，優先導向可執行頁（訓練、排班、Kanban、PDCA）。  
- 驗收：抽查 20 筆工具頁，每筆都有可點的下一步。

### Phase 2（中）— 模板化（四類一致骨架）

- 調查／計劃／配對／混合四類頁面，統一檢核欄：手冊、L1、L2、L3、Next、PDF、匯出。  
- 新頁先套模板再寫內容，既有頁先補最短板（通常是 Next 與 L2 規則解釋）。  
- 驗收：新頁不再出現「有分數、無下一步」。

### Phase 3（中）— 資料契約對齊

- 鎖定主線鍵名（`chp2026_*`、`bible100_smart_ministry*`、`memberSystemData`）。  
- 建立舊鍵到主線鍵的對照表，安排 migration。  
- 驗收：同一主題資料不再雙軌（舊鍵/新鍵）分裂。

### Phase 4（短）— 治理 Gate（防回彈）

- 增加可執行檢核：若 `Next` 不是站內路徑、或主線決策未填，視為未達標。  
- Gate 可先在本機跑腳本，後續再接 CI。  
- 驗收：每次改版可機械驗證，不靠人工記憶。
