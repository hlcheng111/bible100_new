# Digital Academy（church_planning）工具評估共識框架

> 本文從現有頁面、`js/spiritual_health_scoring.js`、`js/strategy_logic.js`、`js/eighty_twenty_engine.js`、`js/church_toolkit.js` 與 `docs/tool-survey-dimension-question-inventory.md` 歸納**跨工具共識**；並標出**尚未完全統一**之處，供後續治理。

---

## 一、我們對「工具型式」的共識

| 層次 | 共識 |
|------|------|
| **載體** | 以單頁 HTML + Vue 3 + Tailwind 為主；資料優先存 **localStorage**（各工具有約定鍵名，如 `chp2026-*`）。 |
| **兩大類工具** | **(A) 量表／問卷型**：固定題項或固定欄位，產出可聚合的數值。**(B) 工作坊／流程型**：多步驟表單、可增刪列、大量文字敘事；數值為輔（清晰度、痛點、負荷等）。 |
| **跨頁資料** | 「教會健康」等結果透過 **統一 health result 結構**（含 `dimensions[]` 的 `id/name/score/max`）讓 SWOT、80/20 等讀取；策略模組再將不同量尺**映射**到內部運算用標度。 |
| **產出物** | 除畫面外，普遍支援 **圖表（Chart.js）**、**PDF／分享文字**，以及（B1）**Markdown／AI Payload** 等可帶入會議的文本。 |

## 二、「質」與「量」的共識

### 2.1 質（設計取向）

- **牧養與治理並重**：分數用於**團隊對話、優先排序、資源配置**，不是替代牧長判斷；B1 等處明確預留「牧長簽註／決議模板」與權責鏈。
- **可理解性**：小白向工具（如 A1）題數少、語境具體；進階工具（NCD、領袖問卷）題數多、覆蓋面完整。
- **與事工現實掛鉤**：題幹多為「過去一段期間的行為／感受／團隊現況」，減少抽象口號。

### 2.2 量（題數與負擔）

| 負擔等級 | 代表工具 | 數量級（約） |
|----------|----------|----------------|
| 極輕 | A1 信徒健康入口 | 5 題 |
| 輕～中 | 信徒靈性自我審查 | 13 題封閉 + 開放 |
| 中 | 領袖健康診斷 | 30 封閉 + 6 開放 |
| 重 | NCD 2026 | 8 維 × 13 題 = 104 題 |
| 可變 | SWOT／SMART／PDCA／80/20 | 以欄位與列數為主，非固定題數 |

**共識**：負擔與深度取捨呈**光譜**；重工具負責「教會級畫像」，輕工具負責「降低進入門檻與回填率」。

## 三、「問的型式」共識

| 型式 | 用途 | 出現位置（例） |
|------|------|----------------|
| **Likert 1–5** | 最常見；維度內聚合、與紅黃綠門檻對齊 | 信徒自查、領袖封閉題、NCD 單題、SWOT 清晰度、SMART 六向度、80/20 痛點／負荷 |
| **Likert 1–6 → 映射 1–5** | 與全站策略運算標度對齊 | A1（正規化後供 B1 `Impact`） |
| **開放式敘事** | 捕捉語境、掙扎、具體行動 | 領袖問卷每維第 6 題、自我審查、PDCA 各行、SWOT 四象限文字 |
| **文本 + 附帶度量** | 策略盤點「說清楚到什麼程度」 | SWOT（S/W/O/T 敘述 + 各 1–5 清晰度） |
| **流程狀態欄** | 執行追蹤而非單次態度 | PDCA（Do 完成度、Check 節奏 1–5、Act 決策類型） |

**共識**：**封閉題負責可比較、可聚合；開放題負責可敘事、可落地**；兩者並存時，報表常註明「摘錄不參與計分」類說明（如 SWOT 與健康診斷連動處）。

## 四、「演算法」共識（含跨模組映射）

以下為程式中**已實作或可歸納**的規則；不同工具量尺不同，**共識是「對內運算前先做明確映射」**。

### 4.1 靈命／領袖類量表（`spiritual_health_scoring.js`）

- **單題**：1–5 計分；若題目為反題則 `6 - 分數`。
- **維度分**：該維度內有效題**算術平均**，保留一位小數。
- **總分**：各維度平均再平均（僅對已有維度）。
- **燈號**：綠 ≥ **4.0**；黃 ≥ **2.8** 且 < 4.0；紅 < 2.8（缺資料視為紅）。

### 4.2 NCD 教會健康（`Church_Health_NCD_planning.html`）

- **維度分**：每維 13 題得分**加總**，滿分 **65**／維。
- **整體指標**：八維分數**算術平均**（介面呈現一位小數）。
- **解讀區間（整體分）**：≥ **52** 健康；≥ **39** 邊際；**< 39** 危機（單維柱狀亦以 **39** 為紅色提示閾值之一）。

### 4.3 SWOT（`swot-planning.html`）

- **清晰度**：每維度 S/W/O/T 各一個 **1–5**「具體度」。
- **與 NCD 連動**：讀取 `loadHealthResult()` 的維度分（預設量尺與 NCD **/65** 一致）；以 **排序後強／弱維度**與**清晰度門檻**組合，產出「優先防禦／優先突破」類**規則式建議**（如弱維 **< 46** 且 W/T 清晰度偏低等條件）。

### 4.4 SMART（`smart-planning.html`）

- **計畫級自評**：六向度各 **1–5** + `Strategic_bonus`（-1～+2）；完成度檢查要求六向度皆選滿後進報告。
- **視覺化**：以六向度為軸畫雷達／長條比較（滿分軸 **5**）。

### 4.5 PDCA（`pdca-planning.html`）

- **定位**：**追蹤做了什麼、學到什麼**，首屏即區隔「不做會友打分」。
- **演算法色彩**：以**行動列狀態、Check 節奏健康度（1–5）、Act 決策分類**為主，**不以單一總分公式**代表全頁「健康」。

### 4.6 80/20 與策略模組（`eighty_twenty_engine.js` + `strategy_logic.js`）

- **事工價值／耗損（legacy 輔助）**：`valueScore = 2×missionFit + 2×fruit - adminBurden`；`wasteScore = 2×adminBurden + (6-missionFit) + (6-fruit)`（1–5 語境）。
- **存廢指數**：**RI = (Impact × G) ÷ Effort**，其中 **G** 為神學權重（核心 1.5／常規 1.0／行政 0.8）；**Impact** 優先 NCD 維度映射至 1–5，其次 A1，再自評；**Effort** 優先 `load_boundary` 映射，其次牧養問卷負荷，再行政負擔組合。
- **修剪門檻**：**RI < RI_PRUNE_THRESHOLD（0.5）** 為紅區建議（常數可全域調）。
- **前 20%**：`ceil(n×0.2)` 且至少 1 項；樣本過少時僅作討論引導（引擎註記）。

## 五、「結果解說」共識

| 手法 | 說明 |
|------|------|
| **分級標籤** | 紅／黃／綠、健康／邊際／危機、RI 紅區與「核心使命但低 RI」錯置警示。 |
| **敘事診斷** | NCD 依分數區間給**文字診斷與行動提示**；80/20 有儀表板摘要 + 模擬 AI 報告 + Payload 供真實 LLM。 |
| **視覺化** | 長條／雷達／儀表卡片，降低一次讀表的認知負擔。 |
| **治理閉環** | 從「系統建議」到「牧長簽註、會議決議、SMART 草稿、localStorage 決議」—**解說必須能接到行動與責任人**。 |
| **免責與界線** | 分數是**起點**；PDCA 等工具在文案上主動**限定用途**（例如不做會友打分）。 |

## 六、目前「尚未完全統一」之處（非矛盾，但需在文件層面對齊）

1. **標度**：同時存在 **1–5**（多數）、**1–6**（A1 入口）、**每維 /65**（NCD）；策略層已用 **映射到 1–5** 方式銜接，但**使用者說明**可再加一段「為何看到不同分數」。  
2. **門檻數字**：靈命問卷（4.0 / 2.8）與 NCD（52 / 39）**不可混用同一組閾值**；共識是**各工具沿用各自門檻**，跨工具只說「相對強弱／排序」。  
3. **文件引用**：`spiritual_health_scoring.js` 註解提到 `docs/SURVEY_DESIGN_PRINCIPLES.md`，倉庫內可能尚未建立—建議補檔或改指向本文與題庫盤點。  
4. **未出題工具**：儀表板／看板等仍以**建議維度**為主，尚未實作題目；共識是未來若出題，應優先採 **1–5 + 維度平均 + localStorage** 與本框架一致。

## 七、一句話共識（給團隊對齊用）
